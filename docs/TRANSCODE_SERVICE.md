# 转码服务：双容器部署

当前部署由 MediaIndex 主容器和 mediaindex-transcoder 配套容器组成。主容器管理画质档位、播放会话、网盘地址和对外 HLS 路由；配套容器负责 FFmpeg、硬件探测、字幕烧录及 HDR 转 SDR。主容器不需要 Docker socket，功能开关不负责启动或停止容器。

前端入口为「转码服务」，地址 #transcode；旧 #plugins 地址仍兼容。只显示内置转码服务，不提供插件安装、插件市场或第三方代码执行。既有 /api/plugins 和 plugins/state.json 暂保留作为旧客户端与部署数据的兼容层，避免升级后丢失开关状态。后续内部命名整理不影响部署方式。

MediaIndex 0.7.38-rc.5 配套 worker 0.1.0-rc.4。两者独立发布；仅更新主界面不重新构建转码镜像。

worker rc.4 修复稀疏 PGS 位图字幕在续播时阻塞视频叠加、堆积 4K HDR 视频帧并触发容器 OOM 的问题。字幕使用独立、同位置的受限输入读取，仍烧录到临时 HLS 分片中。该模式增加一次源文件读取；实际起播速度和持续转码速度仍取决于网盘速度及 NAS 的 HDR 转 SDR 能力。

原画仍走 302，不会自动触发转码。选择指定分辨率和码率时，主服务创建会话，配套容器按需生成临时 HLS 分片供播放器播放，不建立另一份媒体库条目。

SunnyTV 已接入会话与画质接口。其他播放器若拿到可访问、有效的 HLS 地址，可消费标准 HLS 流；原生画质菜单不会自动识别 MediaIndex，需要播放器接入或提供播放地址入口。外网必须正确反代主服务 /api/transcode 路径，配套容器只在内部网络通信。
