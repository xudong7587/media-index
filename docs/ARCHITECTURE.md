# MediaIndex 架构与可靠性边界

`docs/MODULE_BOUNDARIES.md` is the authoritative map for code ownership, allowed dependency direction, regression tests, and the current legacy-debt quarantine. This document records product-level safety invariants; read the boundary map before adding a feature.

## 架构模型

MediaIndex 采用 **Stable Release + Business Modules + Shared Core + Small PR**：每次任务以 GitHub 最新正式 Release 为稳定基线，一个 PR 默认只有一个 Primary Module；只有稳定合同进入 Shared/Core。

业务归属与技术分层是两个维度。`discover`、`tracking`、`transfer`、`strm` 等回答“谁拥有这项行为”；`api / services / providers / clients / db / domain / core` 回答“代码承担什么技术职责”。现阶段保留技术分层，不以模块化为理由批量搬迁现有文件。

目标依赖方向是：

```text
frontend feature -> frontend API contract -> API adapter -> owning service -> domain contract
                                                        |-> provider -> client
                                                        |-> db
```

业务模块不得读取另一个模块的私有实现；跨模块协作通过明确的 service、domain contract、事件或 API 完成。当前逆向依赖和大型 legacy 文件已在 `docs/MODULE_BOUNDARIES.md` 中隔离，并由架构测试阻止继续扩散；渐进迁移必须保持现有 API、配置、数据库、路径、STRM、部署和用户行为兼容。

## 通用 Provider 门面

MediaIndex 的资源验证、文件匹配、改名和转存通过通用 Provider 门面执行。当前主要
Provider 为原生夸克和原生 115，QAS 保留为兼容执行器；MoviePilot 仅可作为 115 Cookie
的导入源或用户自行配置的后处理器，不参与 MediaIndex 的核心转存事务。

一次多网盘操作会创建一个父批次，并按 `provider × season` 拆分为互相独立的子任务。
父批次统一展示进度和结果；一个 Provider 成功、另一个失败时状态为 `partial`，成功结果
必须保留，失败原因进入通知和任务详情，不能回滚或遮蔽成功任务。

## 产品定位

MediaIndex 是部署在个人 NAS 上的媒体发现和转存控制台。后端连接 TMDB、PanSou 与各网盘 Provider，负责目标识别、候选验证、文件匹配、规范命名、任务调度和通知；前端只负责展示、选择和确认。

QAS 是执行器，不是 MediaIndex 的主状态中心。浏览器、历史任务和搜索结果都不能直接指定最终保存路径或绕过后端校验。

## 核心流程

```text
资源名/发现卡片并发取得 TMDB 标准身份和一次 PanSou 资源快照
  -> 以中文标准名为主，剧集最多补第 N 季 / SNN，电影必要时补年份
  -> 按 Provider 独立过滤同一快照中的多个分享链接
  -> 检查目标目录、已播范围和缺失集
  -> 验证快照中的候选或用户明确粘贴的分享链接
  -> 排序候选并读取真实文件树
  -> 综艺匹配集数/期数/日期；电影和电视剧核对名称、年份及季集标记
  -> 预演 pattern / replace 和目标文件名
  -> 高置信度：提交对应网盘 Provider；有效快照不重新搜索
  -> 存在歧义：进入待确认
  -> 各 Provider 独立校验，批次统一执行可选 STRM、Emby 和通知
```

电影、剧集、综艺、网页操作和企业微信指令最终都复用同一套后端任务与校验流程。

发现快照是展示与执行之间的合同：卡片已验证的多个兼容链接必须完整进入本次转存计划；“转存全部”只提交当前可执行的 Provider/季，不等待未知资源；“加入智能追更”才为暂时无资源或后续未播内容登记新一轮显式搜索。夸克与 115 的执行和 STRM 开关始终独立。

OpenList 不属于发现或原生转存。全局自动补齐开启时，夸克资产必须先完成标准命名、目录创建和正式目标逐项核验；随后由统一补齐编排器检查 115，通过 PanSou 搜索并验真可用的 115 分享，优先执行原生 115 转存。OpenList 只复制仍然缺失的精确文件。互动链接和互动搜索先进入云下载暂存，补齐由整理任务在正式落盘后异步触发；暂存路径不能作为 OpenList 自动源。普通正式转存和愿望单共用补齐编排器；智能追更仍要求对应季度显式启用。补齐失败不得回滚或重复夸克 Provider 的成功结果。

## 云下载整理

云下载整理自 GitHub Release `v0.6.15` 正式提供。它的 Primary Module 是 `transfer`；`cloud`、`settings`、`strm`、`integrations` 是 Changed Modules。用户可单选或多选“前序动作事件”与“定时检查”：事件模式只处理 MediaIndex 已知的精确转存目标，定时模式才按配置间隔读取当前授权的云下载一级子目录。Emby 仍通过既有转存后处理接缝刷新，不新增第二套媒体服务器流程。

固定节点顺序为：云下载暂存 → TMDB 身份与命名计划 → 标准文件名和媒体/季度目录 → 最终对象逐项核验 → STRM/Emby 后处理 → 异步 115 补齐（115 目标检查 → PanSou 原生 115 → OpenList 精确差集）。任何前置节点未完成时，后续补齐节点保持未触发。

远程诊断归属 Settings/Security 接缝。登录用户只能创建短时 `diagnostics:read` 令牌；Bearer 接口只读取现有脱敏事件和单任务时间线，令牌摘要存储、默认关闭、限时、限流、可撤销且禁止缓存，不与后台会话或业务 API 授权复用。

```text
MediaIndex 的精确转存任务完成，或定时任务到期
  -> 事件模式从回执取得 Provider、目标路径、文件 ID 或文件名
  -> 定时模式只列举已启用 Provider 的授权一级子目录
  -> 验证 Provider 开关、触发方式和 all/selected 范围
  -> 以同名映射到正式媒体库根的直接子目录
  -> 只读取该任务指向的媒体目录或精确文件
  -> TMDB 高置信度唯一核对与逐视频命名计划
  -> 目标名称冲突预检
  -> 复制或移动计划文件并逐目标核验
  -> 移动模式仅在全部计划完成后按文件 ID 精确清理已复核的残留普通文件
  -> 只为本次目标文件登记资产并定点对账 STRM
  -> 复用 post_transfer_pipeline 触发 Emby 与通知
```

该流程遵守以下不变量：

- 夸克和 115 分别有独立启动开关。云下载根可位于网盘任意绝对路径（包括 `/`），不要求位于正式媒体库根内。`all` 授权当前根下全部可安全映射的直接子目录，`selected` 只授权显式列表；对应目标固定为正式媒体库根下的同名子目录。与目标重叠的来源分支自动排除，浏览器和外部请求不能提交任意目标绝对路径。
- 每次事件只能处理回执明确指向的一级媒体目录或精确文件；不会遍历同一分类中的其他媒体，也不会以扫描兜底。定时模式则只扫描当前授权的直接子目录；云下载根散落文件、范围外路径和与正式库重叠的分支不处理。任务回执不足以唯一定位媒体时 fail closed。
- TMDB 必须得到高置信度唯一结果。电影要求所有视频进入计划；剧集要求所有视频高置信度匹配季度和集数，并始终写入标准季目录。与视频同目录且同 stem 的字幕/NFO 才能作为伴随文件规范命名。
- 目标预检发现同名冲突，或存在未匹配视频、TMDB 歧义、低置信度集数、重复目标名、目录/文件安全上限、Provider 异常时，流程 fail closed，不执行源残留清理。
- `copy` 保留完整来源，不改动源目录或文件；`move` 只有在全部计划文件的目标名称、大小和回执文件 ID 都唯一核验成功后，才重新读取源媒体目录，并只按文件 ID 精确清理当时确认仍位于该目录内的残留普通文件。每次回收站操作都必须在有界轮询内确认精确 ID 消失。整理器绝不回收整个源媒体文件夹；直接文件分组不清理同级其他文件。发现新到达文件、疑似视频、身份或当前授权变化时立即停止。Provider 只使用回收站能力，永不调用永久删除。
- 远端操作以稳定执行键、已保存计划和逐目标强绑定保持幂等。复制 API 提交前先持久化暂存路径、目录 ID、提交前基线 ID 与源文件身份；只有 Provider 调用正常返回后才确认该意图。崩溃恢复只能认领已确认意图之后在绑定暂存目录新出现、且名称/大小唯一符合的 Provider ID；调用未返回、多个候选或无意图文件立即 fail closed。其他异常退出或重试只复用路径、目标文件 ID、名称和大小全部与已持久化核验结果或写回执相符的目标，其余只续作缺失项目。执行中失败或分步清理可能留下已完成的部分远端操作，但不得伪装成成功。
- MediaIndex 自有整理完成后复用 `post_transfer_pipeline`；STRM 只接收本次已核验目标的路径与 Provider 文件 ID。MDC-NG Webhook 的首选模式只把外部完成事件当作信号，对服务端预先选择且已授权的一个 STRM 子目录执行只增不删的增量扫描；外部请求不能覆盖 Provider 或扫描范围。未迁移的旧配置仍兼容安全路径映射。Emby 刷新与通知仍受各自开关约束。

### TG 频道到云下载的入口合同

- 频道订阅负责消息去重、每频道正向/反向词与目标策略；它不直接写正式媒体库。公开频道的关键词搜索由 PanSou 返回候选；MediaIndex Bot 只接收已加入频道后的新帖，不回补加入前历史。
- 帖子里的夸克、115、磁力与 ED2K 链接逐项建立资源记录。只有通过该频道独立关键词规则的资源才能提交；链接与凭据不进入用户可见预览、线程名或普通日志。
- 互动链接未提供显式媒体名时，只读验真得到的分享标题只用于建立独立暂存目录和辅助后续 TMDB 推断，不直接成为正式媒体身份，也不绕过逐文件匹配；无法读取可信标题时才使用稳定链接标识隔离。
- 未启用自动分类时必须选择云下载根下一个实际直属子目录；启用时帖子分类和当前目录映射都必须唯一。任何歧义、缺失目录或 Provider 不可用都 fail closed 并留下可见失败状态。
- 转存统一调用 `direct_link_transfer` 的 `cloud_download` 目的地模式，保留来源命名并触发现有云下载整理。正式目标核验后继续进入同一 `post_transfer_pipeline`，因此 STRM、Emby 和通知没有第二套实现。
- MDC-NG 回执可用正式目标路径将同 Provider 的多个互动/TG 等待任务缩小到唯一项；无路径或过滤后仍不唯一时不修改这些任务。

新增设置保持默认关闭并写入现有配置持久化机制；任务状态复用 `transfer_jobs` 与 `media_workflow_steps`，不新增数据库迁移。Docker Compose、容器路径、卷挂载和升级路径保持不变。

## 自动执行边界

只有同时满足以下条件时才允许自动执行：

- 普通任务通过 TMDB ID 重新解析规范标题、年份、类型、季和目标集；标准电影直通任务必须具备 PanSou 标题、年份和真实文件三重证据。
- 分享链接有效，并能读取用于判断的真实文件列表。
- 每个源文件最多映射到一个目标，且没有错误年份、错误季或重命名冲突。
- 集号、中文期数、播出日期或文件序列提供足够且可解释的证据。
- 候选标题与媒体明确匹配，第一候选达到阈值并与其他候选拉开分差。
- Provider 执行前完成逐文件匹配和目标名称预演。

证据不足时采用 fail-closed 原则：停止自动执行并进入待确认，不扩大匹配范围，也不猜测成功。

## 文件匹配与命名

自动模式优先使用逐文件精确映射：

```text
pattern = ^<escaped source filename>$
replace = <title>.<year>.S<season>E<episode>.<extension>
```

匹配支持标准季集号、中文期数、播出日期和受约束的数字序列。综艺会额外排除加更、纯享、花絮、预告和陪看等衍生内容。任何新增规则都应先加入脱敏回归样本，避免为提高召回率而引入错误转存。

## 路径与安全

- 夸克、115 和本地根路径由服务端分别配置，两个原生网盘各自维护云下载目录；旧 `CLOUD_SAVE_PATH`/`CATEGORY_PATHS_JSON`
  继续作为夸克兼容回退值。
- 115 网盘暂存目录只用于接收、核对、改名和移动；115 本地下载使用单独的容器挂载目录，
  文件先写入同目录临时文件，完成大小校验后再原子替换最终文件。
- 每个网盘维护独立分类子目录；自定义分类键只允许安全标识符，路径禁止点段。
- 最终路径必须由后端拼接，前端不能提交任意绝对路径。
- 密钥只保存在服务端配置中，接口仅返回是否已配置。
- 登录 Cookie 使用服务端会话，敏感 Token 不写入浏览器存储或日志。

## STRM 对账与清理边界

- STRM 生成继续使用 Provider 的分页/批量只读清单；默认不设文件总量上限，本地资产按 500 条事务批写。
- 定点和增量任务只创建、替换和校验映射，不能推进缺失项清理。外部完成事件 Webhook 优先限定到精确文件或目录子树；Cron、115 生活监控和无目标兼容回退仍使用已保存范围增量。
- 清理只允许在完整、非空、未截断的全量枚举后执行，并同时限定 Provider、来源根目录、媒体库标识和所选直接子目录。
- 第一次缺失只进入 `pending_remove` 并保留 STRM 与播放能力；连续第二次完整扫描仍缺失才按已登记精确路径删除。超过范围 10% 或 50 条的删除计划触发熔断。
- Emby 联动删除先以 STRM 相对路径精确映射 115 资产，不按名称猜测且只调用回收站操作；单集和未知类型只删除唯一文件 ID，Emby 明确删除目录或独占电影目录时才按持久化范围删除对应的非根 115 目录 ID。

## 状态与可靠性

- 同一媒体、季和保存目标只允许一个运行中、待执行或待确认任务。
- QAS、Cookie 或目录查询异常不能退化为“目录为空”或“任务成功”。
- 媒体详情只在用户启动单盘或全部转存后展开本批次链路；已启用网盘各占一条独立链，未参与本次批次的网盘明确显示“本次未启动”。
- “提交网盘”和“落盘确认”是两个状态：原生夸克、原生 115 与 QAS 必须验证目标目录及预期文件后才能完成落盘节点；只提供外部提交回执的执行端会显示未由 MediaIndex 核验。
- SQLite 启用 WAL、外键和 busy timeout；进程重启时会恢复或标记中断任务。
- 展示接口不得触发调度计算或数据库状态变化。

## 通知与交互

转存完成、任务提交、待确认、暂无资源和失败事件先写入站内通知，再按配置以海报图文优先的形式推送到 Telegram、企业微信群机器人或企业微信自建应用；无可访问图片时回退文字。

企业微信回调经过签名校验、AES 解密、企业 ID 校验、成员授权和重复投递去重。资源搜索存在歧义时返回编号候选，用户确认后才创建任务；待确认任务同样复用网页端的安全确认逻辑。

外部完成 Webhook 使用独立密钥认证，外部 Body 不能指定 Provider 或扫描路径。首选模式按服务端预选的一个已授权 STRM 子目录合并连续完成事件并执行只增不删的增量扫描；未迁移旧配置仍保留原安全路径映射。MDC-NG 只是可接入的外部服务之一。

通用 Webhook 与 MDC-NG 专用适配器分层：MDC-NG 保留既有 URL、鉴权和 STRM 业务语义；通用接收端只把通过鉴权和事件 ID 去重的 CloudEvents 写入事件箱，不执行任意业务命令。通用发送端只订阅已经持久化的标准通知事件，通过持久化投递箱、Standard Webhooks 签名和退避重试发送；只有目标返回 `2xx` 才进入已验证状态。公网目标要求 HTTPS，局域网和 Docker HTTP 属于自托管兼容边界，客户端禁止重定向。
