# MediaIndex 使用手册

本手册按真实使用顺序说明 MediaIndex 的全部主要功能。你不必一次配置所有服务：先连接一个网盘并完成一笔小任务，再逐步启用 STRM、Emby、追更和通知，通常最容易判断每一步是否符合预期。

## 1. 先理解 MediaIndex 的使用方式

MediaIndex 是个人媒体工作流的控制台，不是资源站，也不是新的网盘或媒体服务器。它连接你自己的服务，帮助你完成五类事情：

1. **发现与输入**：通过 TMDB 浏览内容、通过 PanSou 或频道搜索，或直接提交已有链接。

2. **确认与转存**：选择媒体、季数、候选资源、目标网盘和保存位置。

3. **整理与维护**：用分类、命名、追更和愿望单保持网盘目录长期可用。

4. **建立媒体库**：从明确选择的网盘目录生成 STRM，让 Emby 扫描和播放。

5. **观察与处理**：从任务中心、待确认、活动记录和消息渠道了解结果。

### 1.1 主导航

| 页面 | 主要用途 |
| --- | --- |
| **发现** | 浏览榜单和分类、搜索媒体、打开详情、转存或加入愿望单与追更。 |
| **订阅与追更** | 管理智能追更、愿望单、缺集检查和手动补齐。 |
| **网盘工作台** | 连接网盘、设置资源来源、配置转存整理规则、查看任务。 |
| **跨盘转存** | 通过 OpenList 在两个已挂载服务之间手动复制文件或目录。 |
| **STRM 与 302** | 配置播放入口，分别管理 115 和夸克的 STRM，并设置 Emby 联动。 |
| **媒体服务器** | 查看 Emby 运行概况、媒体库、用户、播放会话、最近入库和封面。 |
| **全局设置** | 配置 TMDB、OpenList、网络代理、通知、聊天交互和 Webhook。 |

页面右上角的通知与活动入口用于快速查看最近发生的事情。遇到任务无结果、需要选择候选或执行失败时，优先从这里和任务中心进入详情。

## 2. 部署

### 2.1 准备目录

```bash
mkdir -p media-index/{data,downloads,strm}
cd media-index
```

这些目录分别承担以下用途：

- `data` 保存数据库、网页设置和应用数据，是最重要的备份对象。

- `downloads` 用于需要本地输出的任务；不用时也可以保留空目录。

- `strm` 保存生成的 STRM 文件，应与 Emby 扫描的目录对应。

### 2.2 Docker Compose

保存为 `docker-compose.yaml`：

```yaml
services:
  media-index:
    image: ghcr.io/xudong7587/media-index:latest
    pull_policy: always
    container_name: media-index
    ports:
      - "8000:8000"
      - "8097:8097"
    environment:
      MEDIA_USER: admin
      MEDIA_PASS: change-this-password
      MEDIA_CONFIG_PATH: /app/data/.env
      DB_PATH: /app/data/media_index.db
      CACHE_DIR: /app/data/cache
      STRM_OUTPUT_ROOT: /strm
      MEDIA_PLAYBACK_INTERNAL_PORT: 8097
      PUID: ${PUID:-10001}
      PGID: ${PGID:-10001}
    volumes:
      - ./data:/app/data
      - ./downloads:/downloads
      - ./strm:/strm
    restart: unless-stopped
```

启动前必须把 `MEDIA_PASS` 改为强密码。应用会拒绝空密码以及密码 `admin`。

```bash
docker compose up -d
```

然后访问 `http://NAS_IP:8000`。

### 2.3 两个端口分别做什么

| 默认端口 | 用途 | 谁需要访问 |
| --- | --- | --- |
| `8000` | 管理面板与 API | 浏览器、企业微信或其他调用 Webhook 的服务。 |
| `8097` | STRM/302 播放入口 | Emby、电视、手机和其他实际播放设备。 |

如果 NAS 端口冲突，只改 Compose 左侧，例如 `24680:8000` 和 `24697:8097`。容器内部端口保持不变。

管理地址与播放地址不是一回事。STRM 中应写入所有播放器都能访问的 `8097` 映射地址或反向代理域名，不能填写管理端口，也不要填写 `127.0.0.1`。

### 2.4 目录权限

如果 NAS 要求指定目录所属用户，可在 Compose 同级 `.env` 中设置 `PUID` 和 `PGID`。至少确认：

- 容器可以读写 `./data`。

- 容器可以在 `./strm` 创建、更新和清理自己生成的 STRM。

- Emby 能读取同一 STRM 目录；如果两个容器看到的路径不同，后续删除联动应填写 Emby 事件中实际出现的路径。

### 2.5 可选：同时部署 PanSou

仓库的 `docker-compose.yaml` 已附带注释状态的 PanSou 服务和缓存卷。需要站内搜索时，取消 `pansou` 服务与 `pansou-cache` 卷的注释，再重新执行：

```bash
docker compose up -d
```

随后在 **网盘工作台 → 资源获取 → PanSou 聚合搜索** 填写 `http://pansou:8888`。如果你已经在别处部署 PanSou，无需重复启动，只要填写 MediaIndex 容器能够访问的地址。

## 3. 第一次配置：建议顺序

按以下顺序完成一个最小闭环，再扩大自动化范围：

1. 在 **网盘工作台 → 网盘连接** 启用夸克或 115，保存凭据并点击测试连接。

2. 在 **全局设置 → 全局设置** 填写 TMDB API，保存并测试。

3. 需要站内找资源时，在 **网盘工作台 → 资源获取** 配置 PanSou；已有链接则可以跳过。

4. 在 **转存和整理规则** 设置目标网盘的保存根目录、暂存目录、分类与命名。

5. 在发现页选择一部熟悉的电影，完成一次小范围转存并核对网盘结果。

6. 在 **STRM 与 302** 配置播放地址和一个来源子目录，先运行一次全量扫描。

7. 连接 Emby，确认媒体库扫描和实际播放正常。

8. 最后再开启追更、愿望单、定时扫描、通知、OpenList 或删除联动。

设置页有未保存内容时，离开页面会收到提示。保存后的密钥通常只显示“已配置”，不会在网页重新明文显示。

## 4. 发现：从“想看什么”开始

### 4.1 浏览与筛选

发现页通过 TMDB 展示电影和剧集信息。你可以使用：

- 热门、趋势、口碑和平台榜单浏览内容。

- 电影、电视剧、动漫、综艺等分类缩小范围。

- 关键词搜索中文名、英文名或其他已知名称。

- 分页继续查看结果。

开启成人内容筛选后，发现推荐和搜索会隐藏 TMDB 标记为成人内容的条目。

### 4.2 媒体详情

打开卡片后可以看到海报、简介、年份、评分、类型和剧集季信息。详情页是一次转存的确认入口：

- 电影直接选择目标网盘和候选资源。

- 剧集可以选择一季或多季，并查看每季集数。

- 已启用多个网盘时，可以根据候选来源选择夸克或 115。

- 页面可以打开或复制最高可信度的分享链接，供你自行复核。

- 暂时不想转存时，可以加入愿望单；需要持续跟进连载时，可以创建智能追更。

- 配置了本地保存路径时，可以选择“存本地”；它与“转存全部网盘”是不同目标。

确认前请重点核对标题、年份、季数和候选描述。证据不足或候选不唯一时，任务可能进入待确认，而不是直接执行。

### 4.3 单次转存

一次典型操作是：

1. 打开媒体详情并选择电影或季。

2. 选择已启用且已连接的目标网盘。

3. 查看候选名称、清晰度和来源提示。

4. 确认提交。

5. 到 **网盘工作台 → 任务中心** 查看查询、确认、转存、整理和后续动作。

如果规则已启用自动 STRM，转存完成后会继续生成相应媒体库文件；否则可以稍后手动运行增量扫描。

已配置 OpenList 且本次确实需要补齐另一侧时，可以在详情页标记转存完成后同步；没有标记时，单次任务不会因为安装了 OpenList 就自动扩大复制范围。

### 4.4 多季内容

多季剧集可以按季选择。建议先处理一季确认目录结构，再批量提交其他季。每季会保留自己的任务状态；其中一季失败不代表其他季一定失败。

### 4.5 直接提交链接

发现页与聊天渠道都可以接收已有链接，系统根据链接类型选择网盘：

| 输入 | 执行目标 |
| --- | --- |
| 夸克分享链接 | 夸克 |
| 115 分享链接 | 115 |
| 磁力、ED2K、HTTP/HTTPS 下载链接 | 115 |

直接下载使用 **全局设置 → 通知和交互 → 云下载设置** 中对应网盘的云下载目录。链接不等于影视资料时，不要求先经过发现页。

## 5. 网盘工作台

### 5.1 网盘连接

夸克和 115 可以同时启用，也可以只使用其中一个。每个网盘都有独立的连接状态和执行开关。

#### 启用与停用

- **启用**：参与发现转存、愿望单、智能追更和对应网盘任务。

- **停用**：立即停止参与新的自动任务，但不会删除凭据、历史任务、网盘文件或现有 STRM。

系统至少需要保留一个执行网盘。准备切换网盘时，应先连接并测试新的网盘，再停用旧网盘。

#### 保存凭据与测试

在对应卡片中粘贴自己的 Cookie 或登录凭据，保存后点击测试连接。测试通过只说明当前凭据可访问服务；保存目录和规则仍需单独配置。

凭据失效时，通常表现为测试失败、新任务无法读取目录或转存失败。重新获取凭据并保存，不需要重建数据库或删除历史任务。

### 5.2 资源获取

这一页决定“去哪里找候选”，不决定候选是否一定转存。

#### PanSou 聚合搜索

填写 PanSou 地址并测试连接。若 PanSou 与 MediaIndex 在同一 Compose 网络中，可填写容器地址，例如 `http://pansou:8888`；如果独立部署，则填写 MediaIndex 容器能够访问的地址。

PanSou 可用于发现详情、愿望单和追更的候选搜索。关闭或不可用时，已有直链、频道候选和网盘内已有内容不受影响。

#### Telegram 频道来源

你可以维护公开或私有频道作为候选来源：

- 公开频道会在保存频道以及实际搜索资源时按需更新。

- 私有频道需要 Telegram Bot 能够读取对应消息。

- 频道中的夸克与 115 链接会作为候选参与发现、愿望单和追更。

- 导入频道后默认可作为搜索来源；是否允许自动转存仍由你在页面中设置。

页面支持从 PanSou 发现并导入频道。建议先导入少量可靠频道，观察候选质量后再扩大范围。

Telegram Bot 同时用于频道接收和聊天交互，但两种用途可以分别决定是否启用。

### 5.3 转存和整理规则

#### 保存根目录与暂存目录

每个网盘分别设置：

- **保存根目录**：分类目录的上层位置。

- **暂存目录**：需要先接收再整理的内容放置位置。

- **云下载目录**：直接链接或聊天下载命令的默认落点。

- **本地保存或兼容目录**：只有明确选择“存本地”或使用需要本地文件的兼容任务时才使用；不是常规网盘转存的目标。

用页面的目录选择器浏览并确认路径，避免手工输入时混淆两个网盘的目录格式。

#### 分类路径

电影、电视剧、动漫和综艺可以分别保存到不同子目录。更改规则只影响之后的任务，不会主动移动已经整理好的历史内容。

#### 命名与版本

命名规则用于统一标题、年份、季目录和版本信息。画质顺序用于多个候选都可用时表达偏好。建议：

1. 先用默认规则完成一部电影和一季剧集。

2. 核对中文标题、年份、季目录和版本标签。

3. 再根据现有 Emby 媒体库习惯调整。

不要在没有样例验证的情况下同时改变根目录、分类和命名，否则出现结果偏差时很难判断是哪项规则造成的。

#### 云下载整理

这项能力自 GitHub Release `v0.6.15` 正式提供。配置入口位于 **网盘工作台 → 转存和整理规则 → 云下载整理**，与“通用规则”“夸克规则”“115 规则”同级。

云下载整理用于把已经下载到夸克或 115 云下载目录中的内容，核对并规范转存到同一网盘的正式媒体库。首次使用建议按以下顺序配置：

1. 在“夸克规则”或“115 规则”中连接对应网盘，分别设置正式媒体库根和云下载根；在全局设置中配置可用的 TMDB API Key。

2. 在云下载根下按正式媒体库分类建立直接子目录。例如云下载根是 `/媒体库/下载文件夹`、正式媒体库根是 `/媒体库`，则 `/媒体库/下载文件夹/01电影` 固定映射到 `/媒体库/01电影`。

3. 回到“云下载整理”，点击对应网盘的“读取一级子目录”，只勾选需要自动整理的范围。系统不会默认整理整个云下载根，也不会处理根目录散落文件或未勾选目录。

4. 选择复制或移动模式，设置自动检查间隔和文件稳定等待时间，再保存规则。两个时间字段范围均为 1–1440 分钟；总开关默认关闭，升级后不会自行扫描或移动已有文件。

5. 先用一个可恢复的小目录点击“整理 115”“整理夸克”或“立即整理全部”，并在任务中心核对来源、目标、标准名称和后处理结果；确认无误后再等待定时执行。

每个已选一级子目录都只作为分类范围。真正进入整理的可以是它下面的一级媒体目录，也可以是直接放在该分类下、文件名能安全提取标题的媒体文件，例如：

```text
/媒体库/下载文件夹/01电影/待整理影片
  -> /媒体库/01电影/标准片名 (年份)/标准文件名
/媒体库/下载文件夹/01电影/片名.2026.mkv
  -> /媒体库/01电影/片名 (2026)/片名.2026.mkv
```

直接文件会按清洗后的标题、年份和剧集标记保守分组；只有 `S01E01`、`CD1` 而没有文本标题的文件不会仅凭集数猜测 TMDB 身份。同 stem 字幕/NFO 可跟随所属视频；移动模式只移动该安全分组的计划文件，不会清理已选分类下的其他同级文件。

应用启动后的调度会先检查一次，之后按自动检查间隔继续扫描。整理单元第一次被看到时只记录文件清单指纹；只有目录结构、文件标识、路径和大小在整个稳定等待时间内不再变化，才进入 TMDB 核对。期间继续下载或新增文件会以新的指纹重新等待，避免整理尚未完成的下载。

TMDB 与命名采用保守规则：

- 目录名必须能得到高置信度且与次选拉开差距的唯一 TMDB 结果；无结果或多个接近结果进入待确认，不执行网盘写操作。

- 电影目录中的每个视频都必须纳入唯一计划，随后建立标准媒体文件夹并规范文件名。

- 剧集的每个视频都必须高置信度匹配到明确季度和集数；正式媒体库始终按现有季度文件夹规则建立季目录（默认模板为 `Season {season}`），再写入标准集文件名。

- 与视频位于同一源目录、且以同一完整 stem 开头的字幕或 NFO，会跟随该视频规范改名和转存。不能唯一关联的字幕、NFO、图片及其他文件不会被猜测配对。

两种转存模式的来源处理不同：

| 模式 | 目标与来源行为 |
| --- | --- |
| **复制** | 通过暂存目录复制、改名并转入正式媒体库；目标逐项核验成功后完成，原云下载目录和文件保持不变，不执行来源清理。 |
| **移动** | 先改名并移动全部计划文件，逐个目标目录核验名称、大小和回执文件 ID；全部目标唯一确认后，系统会重新读取源媒体目录，只按文件 ID 精确清理当时确认仍在该目录内的残留普通文件，并在有界轮询内确认该 ID 消失。不会回收整个源媒体文件夹；回收站操作不是永久删除。 |

移动清理前会再次核对残留文件仍属于原媒体目录；如果期间出现新到达文件、疑似视频、文件身份变化或目录范围变化，清理会立即停止并在任务中提示，不会把并发写入误当成旧残留。未匹配视频、TMDB 歧义、命名碰撞、目标已有同名文件、目录过深、文件过多、连接异常或任一步失败，同样不会触发源残留清理。

移动模式的远端操作不能跨步骤回滚；如果故障发生在部分文件已经移动或部分普通残留已进入回收站之后，MediaIndex 会记录失败，需在任务中心同时核对源目录和已产生的目标，不能把失败理解为“完全没有写入”。复制模式会在调用 Provider 前记录暂存目录 ID、提交前文件 ID 基线和本批源文件身份，并只在 Provider 调用正常返回后确认该意图。重启后只会认领已确认意图之后在该暂存目录新出现、且名称/大小唯一符合的 Provider ID；调用超时或未返回、多个候选及无意图文件都会安全停止并等待人工核对。其他异常重启或重试只会复用与持久化回执的目标路径、目标文件 ID、名称和大小全部相符的结果，只续作缺失项目。写入期间新到达的文件会转入新的稳定周期，不会永久重放旧清单。这一幂等恢复复用现有转存任务记录，不要求数据库迁移。

目标完成后会复用现有 `post_transfer_pipeline`：按对应网盘已经保存的开关和目录范围执行增量 STRM，再按既有设置刷新 Emby、发送入库或失败通知。云下载整理不会扩大 STRM 来源范围，也不会绕过 STRM、Emby 或通知各自的开关；未配置或不在范围内的步骤会按既有规则跳过或记录结果。

为避免从旧版升级后把曾因调度条件未满足而积压的入库通知集中补发，延迟入库通知队列只投递 24 小时内的待发事件；更旧记录保留在通知表中，并标记为已跳过及其原因。

此功能新增独立的网页配置字段，并复用现有转存任务与媒体工作流记录，不要求数据库迁移，也不改变 Docker Compose、容器路径或挂载方式。关闭总开关只停止自动扫描，不会删除已保存范围、历史任务、网盘文件或现有 STRM。

### 5.4 任务中心

任务中心集中展示发现转存、追更、愿望单、STRM 和其他后台任务。你可以查看：

- 任务标题、来源、目标网盘、创建时间和当前状态。

- 当前执行阶段与最近消息。

- 成功结果、失败原因或需要确认的候选。

- 重试、确认或进入相关页面处理的入口。

常见状态可以这样理解：

| 状态 | 含义 | 建议 |
| --- | --- | --- |
| 等待或排队 | 已接收，尚未开始 | 等待当前任务完成。 |
| 运行中 | 正在查询、转存、整理或生成 | 不要重复提交同一操作。 |
| 待确认 | 不能可靠选择候选 | 打开详情人工选择或重新搜索。 |
| 暂无资源 | 当前没有合适候选 | 稍后重试，或交给愿望单/追更。 |
| 失败 | 服务、凭据、路径或网络出错 | 先读错误信息并测试相关连接。 |
| 完成 | 本次任务已经结束 | 核对网盘、STRM 或 Emby 结果。 |

## 6. 订阅与追更

这一页包含两种不同需求：**愿望单**用于“现在可能还没有资源，之后再找”，**智能追更**用于“已经在看或已入库，持续核对更新和缺集”。

### 6.1 智能追更

#### 创建追更

从剧集详情选择要追踪的季和执行网盘。创建后应确认：

- 作品和季数正确。

- 保存路径与已有目录一致。

- 已存集数符合网盘实际内容。

- 任务处于启用状态，并显示合理的下次检查时间。

#### 巡检计划

订阅与追更页可以开启或关闭自动巡检，并设置追更时间、轮询周期、无资源后的重试间隔和最多巡检次数。关闭自动巡检后，卡片上的“立即运行”仍然可用。

建议把追更时间设在常见发布时间之后，并避免与大量 STRM 或备份任务集中在同一分钟。

#### 如何理解进度

追更卡片同时展示两个事实：作品按 TMDB 信息已经播出到哪里，以及你选择的网盘目录已经保存到哪里。只有出现需要补齐的内容时才会搜索候选。

TMDB 的播出状态不是网盘文件清单；网盘里出现额外花絮、命名不规范或错误季目录时，可能需要你修正保存路径或手动选择集数。

#### 运行、暂停和删除

- **立即运行**：现在执行一次核对，不改变之后的计划。

- **暂停**：保留任务和历史状态，但停止后续自动检查。

- **恢复**：重新参加计划任务。

- **删除追更**：只删除追更记录，不删除网盘文件、STRM 或 Emby 媒体。

#### 手动补齐

当你明确知道缺少哪些集时，可以选择目标集手动补齐。手动补齐只处理本次选择，不会自动回补所有历史缺口。

#### 暂无资源与待确认

“暂无资源”表示本次没有找到合适候选，可以保留任务等待下次检查。“待确认”表示存在候选，但系统无法安全决定，需由你查看并选择。两者不应混为一谈。

### 6.2 愿望单

愿望单适合尚未上映、刚上线或暂时没有可靠资源的内容。每个条目可以选择目标网盘、启用、暂停、立即检查或移除。

全局愿望单计划可以设置检查日期、小时和执行网盘。关闭全局巡检不会删除条目；单个条目的暂停也不会影响其他愿望。

找到并完成转存后，查看任务中心确认结果。没有资源时条目会继续保留，不需要反复手工添加。

## 7. 待确认、活动与站内通知

### 待确认

待确认用于承接“有结果，但不能替你做决定”的情况。打开条目后可以：

- 查看媒体标题、年份、季集和触发来源。

- 比较候选名称、网盘、画质与上下文。

- 选择一个候选继续。

- 重新搜索或暂不处理。

处理前不要只看文件名中的清晰度，还应核对作品年份、季数和集数。错误确认可能把内容保存到错误目录。

### 活动记录与通知中心

活动记录按时间展示网盘、追更、STRM、Emby 和通知任务。站内通知突出需要关注的成功、失败和待处理事件。它们用于观察和跳转，不替代任务中心的完整详情。

### 运行日志

日志适合排查连接、路径、第三方服务或后台任务问题。对外求助时可提供：

- 发生时间与操作入口。

- 任务标题和状态。

- 已隐去 Cookie、Token、分享凭据和私人路径的相关日志片段。

不要公开完整配置文件或带查询参数的私密 URL。

## 8. 跨盘转存

跨盘转存依赖 OpenList。它适合在两个已经挂载到 OpenList 的存储服务之间手动复制，不是发现页常规转存的必经步骤。

### 8.1 使用前配置

在 **全局设置 → OpenList 同步** 填写：

- OpenList 地址与 Token。

- 夸克和 115 在 OpenList 中对应的媒体库路径。

- 需要自动联动时选择允许的复制方向。

保存并测试连接后，再进入跨盘转存。

### 8.2 手动复制

页面左右两侧分别浏览源和目标目录。你可以：

- 按名称、类型或时间排序。

- 选择一个或多个文件、目录。

- 指定目标位置并提交复制。

- 选择如何处理目标端已存在内容。

- 在任务监视区域查看进度和结果。

提交前仔细确认左右方向和目标目录。跨盘复制会产生第三方服务流量与空间占用；目标端同名内容的处理策略应按你的数据习惯选择。

### 8.3 自动联动

开启 OpenList 自动同步后，发现转存、愿望单或追更完成时，可以按已保存方向复制新内容。智能追更的自动补齐只针对缺失集，不等同于复制整个媒体目录。

手动复制不受自动方向限制。首次启用自动联动前，建议先用一个小文件验证两侧路径。

## 9. STRM 与 302

STRM 是 Emby 媒体库中的轻量入口文件。MediaIndex 在本地生成 `.strm`，播放时由单独的 302 入口把请求带到对应网盘文件。

### 9.1 STRM 通用设置

#### 播放地址

填写播放器实际能够访问的完整地址：

- 仅内网使用：例如 `http://NAS_IP:8097`。

- 反向代理：填写代理到播放端口的 HTTPS 域名。

- 宿主机映射不是 8097：填写实际映射后的端口。

不要填写管理端口 `8000`，也不要填写 `localhost` 或 `127.0.0.1`。Emby、电视和手机会把 `127.0.0.1` 理解成各自设备本身。

#### Emby 连接与自动刷新

填写 Emby 地址和 API Key 并测试连接。开启“STRM 完成后刷新 Emby 媒体库”后，STRM 新增或更新会通知 Emby 扫描；媒体识别与元数据下载仍由 Emby 负责。

### 9.2 115 STRM 与夸克 STRM

两个页面的操作方式一致，但配置和任务彼此独立。

#### 选择来源范围

1. 选择网盘中的 STRM 来源根目录。

2. 点击“读取子目录”。

3. 明确勾选需要扫描的直接子目录。

4. 保存本页设置。

未勾选任何目录时不会扫描。勾选后只递归读取所选目录；根目录散落文件和其他未选目录不会被顺带处理。这里的来源目录不会改变网盘工作台中的转存保存规则。

#### 输出目录

默认容器路径是 `/strm`。通过 Compose 将它挂载到 Emby 能扫描的位置。如果多个媒体库共用一个输出根，请确保分类结构能被 Emby 正确区分。

#### 全量与增量扫描

| 模式 | 适用场景 |
| --- | --- |
| **全量扫描更新** | 首次建立、修改播放地址、调整来源范围或整体校正。 |
| **增量扫描** | 日常新增内容后快速更新。 |

两种扫描都只读取网盘目录信息，不会移动或删除网盘文件。全量扫描可以清理 MediaIndex 自己生成、但已不再对应当前范围的本地 STRM 映射；因此调整来源范围前仍应备份 STRM 目录。

#### 自动生成与定时任务

开启某个网盘的自动 STRM 后，该网盘转存成功会扫描本页已保存的范围。定时增量扫描使用标准 5 段 Cron：

```text
分 时 日 月 周
```

例如 `0 */6 * * *` 表示每 6 小时的整点执行。留空即关闭定时增量。自动任务和手动任务使用相同的来源范围。

#### 115 生活事件监控

如果另一个 Docker 或整理工具会向 115 目录写入内容，可以开启生活事件监控：选择监控子目录和 30–3600 秒检查间隔。首次开启只建立当前基线，不会重复处理历史事件；发现后续变化时，再按已保存范围执行增量扫描。

### 9.3 外部完成 Webhook

外部刮削器或整理器完成一批工作后，可以通知 MediaIndex 运行一次增量 STRM。入口位于 **全局设置 → 通知和交互 → Webhook**。

在网页中生成并保存密钥、选择目标网盘，并确认页面显示的扫描范围。调用示例：

```bash
curl -i -X POST 'http://media-index:8000/api/webhooks/strm-incremental?token=完整密钥'
```

Webhook 使用管理/API 端口，不使用播放端口。返回 `HTTP 202` 且状态为 `scheduled` 或 `coalesced`，表示已接收或与短时间内的重复事件合并。

常见返回：

| 状态 | 含义 |
| --- | --- |
| `401` | 密钥缺失或不正确。 |
| `409` | 当前保存的网盘或扫描范围不满足执行条件。 |
| `503` | 对应服务当前不可用或任务无法排入。 |

该入口只使用网页中已经保存的网盘和来源范围，并执行只增不删的增量任务；外部请求不能临时指定任意目录。

### 9.4 115 删除同步

删除同步用于在 Emby 删除一条由 MediaIndex 生成的 115 STRM 时，将精确对应的 115 文件移入回收站。

配置步骤：

1. 在 **STRM 与 302** 连接 Emby，并确认 115 STRM 正常生成。

2. 打开 115 删除同步，生成并保存 Webhook 密钥。

3. 填写 **Emby 中的 STRM 媒体库根目录**。它必须是 Emby 删除事件里看到的路径，不一定等于 MediaIndex 容器内的 `/strm`。

4. 将页面给出的 Webhook 地址填入 Emby，并只选择你确实需要的事件。

5. 先用一条可恢复的测试媒体验证路径映射，再考虑开启自动执行。

安全边界：

- 只处理已登记且能精确对应的 115 STRM。

- 只移入 115 回收站，不提供彻底删除。

- 目录级、名称猜测、路径不一致或缺少映射时会拒绝自动删除。

- 夸克删除同步当前未开放，不会借用 115 的设置。

请把回收站保留时间当作最后保护层，并定期检查空间与恢复策略。

## 10. 媒体服务器

连接 Emby 后，媒体服务器页面提供一个日常观察面板：

- 服务器名称与连接状态。

- 电影、剧集、单集等内容数量。

- 媒体库列表和封面。

- 用户、活跃播放会话和最近入库。

- 手动刷新页面数据。

此页面用于查看和辅助维护，不替代 Emby 自己的用户、媒体库和转码设置。

### 10.1 媒体库封面工坊

封面工坊只在你打开预览、立即替换或定时任务运行时使用。预览不会写入 Emby，点击替换后才会修改媒体库封面。

#### 基本流程

1. 选择一个媒体库作为预览。

2. 选择 1080p、720p 或 480p 输出规格。

3. 选择风格并调整标题、图片来源、背景和文字。

4. 点击“重新取样”更换用于预览的海报组合。

5. 满意后只替换当前预览库，或替换全部勾选媒体库。

#### 四种静态风格

- 风格 1：圆角卡片堆叠。

- 风格 2：单海报斜切构图。

- 风格 3：九宫海报矩阵。

- 风格 4：柔焦极简标题。

#### 可调项目

- 海报图或背景图作为图片来源。

- 随机、入库时间或首播日期排序。

- 模糊背景、渐变背景、自动取色或自定义颜色。

- 每个媒体库独立保存中英文标题。

- 全部媒体库共用字体、字号、位置、间距、缩放、模糊和颜色比例。

- 上传 `.ttf`、`.otf` 或 `.ttc` 字体文件，单个文件最大 12 MB。

#### 定时替换

开启定时更新后填写 5 段 Cron，并选择要处理的媒体库。不勾选时代表全部媒体库；勾选后，批量生成和定时任务只处理所选库。建议先对一个媒体库手动验证，再开启定时替换。

## 11. 全局设置

### 11.1 全局设置

#### TMDB

TMDB 为发现、海报、详情、季集和播出状态提供资料。保存 API 后点击测试。TMDB 不负责提供下载资源。

#### 成人内容筛选

开启后，发现推荐和搜索结果隐藏 TMDB 标记为成人内容的条目。它只影响展示筛选，不是家庭网络内容审查工具。

#### 配置导入导出

“导出全部设置”会下载一个 JSON，包含网页设置、网盘凭据、目录、智能追更和愿望单。它适合迁移配置或在升级前保留一份应用级备份，但不能替代整个 `data` 目录的文件备份。

“导入并覆盖”会用所选 JSON 覆盖当前同类设置和任务。导入前应先导出当前配置，并确认文件来自可信部署。导出的 JSON 含 Cookie、Token 等敏感信息，不要截图、转发或提交到 Git。

### 11.2 网络代理

当容器无法直接访问 TMDB、Telegram 或其他外部服务时，可以在网络代理页填写代理。保存后分别测试受影响的服务；代理地址必须能从 MediaIndex 容器内部访问。

不要把浏览器所在电脑的 `127.0.0.1` 代理直接填给 NAS 容器，除非代理确实监听 NAS 可访问的地址。

### 11.3 OpenList 同步

这里保存 OpenList 地址、Token、两侧媒体库目录、自动同步开关和允许方向。路径是 OpenList 中的挂载路径，不是 NAS 本地文件系统路径。

自动方向只约束自动联动；跨盘转存页的手动任务，以及追更卡片中明确发起的手动补齐，不受该方向限制。

## 12. 通知和交互

### 12.1 通知

先打开外部消息总开关，再选择要推送的事件：

- 转存完成。

- Emby 入库完成。

- 需要确认。

- 暂无资源。

- 处理失败。

- Emby 播放事件。

“公网访问地址”用于消息跳转、企业微信回调和海报访问，应填写手机或消息平台能够访问的 MediaIndex 地址，不要带具体页面路径。

#### 企业微信自建应用

填写 CorpId、应用 Secret、AgentId 和接收成员、部门或标签。多个接收对象用竖线分隔；`@all` 表示应用可见范围内的全部成员。保存后发送测试消息。

“微信消息代理地址”只用于 MediaIndex 向企业微信发送消息；没有代理时使用官方地址。它不是企业微信后台的回调 URL。

#### 企业微信机器人

填写机器人 Webhook，启用并测试。机器人适合群内通知；需要成员发送指令时，应使用自建应用回调。

#### Telegram

填写 Bot Token、Chat ID 等页面要求的项目，保存后发送测试消息。用于私有频道或交互时，确保 Bot 已加入相应会话并拥有读取或发送权限。

### 12.2 交互指令

企业微信自建应用和 Telegram 共用一套指令与网盘规则。可以选择允许使用的网盘，并把常用指令同步到企业微信菜单或 Telegram 命令列表。

| 输入或指令 | 用途 |
| --- | --- |
| 资源名称 | 搜索候选并返回可选结果。 |
| `本地 资源名称` | 搜索影视，并把确认后的内容保存到已配置的本地路径。 |
| 夸克或 115 分享链接 | 转存到对应网盘的云下载目录。 |
| 磁力、ED2K、HTTP/HTTPS 链接 | 提交到 115 云下载目录。 |
| 数字 | 在当前会话中选择候选、目录或确认项。 |
| `/review` | 查看待确认项目。 |
| `/status` | 查看最近任务状态。 |
| `/tracking` | 查看智能追更。 |
| `/wishlist` | 查看愿望单。 |
| `/strm_full` | 对允许的网盘运行全量 STRM。 |

| `/strm_directory` | 列出已配置来源根目录的一级子目录，回复数字选择扫描。 |

数字回复只对当前会话中最近的待选择步骤有效。候选或目录发生变化时，应重新发起指令，不要沿用旧数字。

#### 企业微信交互回调

在通知页启用回调，填写企业微信后台生成的 Token、EncodingAESKey 和允许成员。把页面生成的回调 URL 填入企业微信后台并完成验证。

若回调验证失败，依次检查公网地址是否可达、HTTPS 证书、Token/AESKey 是否一致，以及反向代理是否保留查询参数。

### 12.3 云下载设置

这里决定聊天指令和发现页直接粘贴链接的保存位置，并展示最近的交互转存记录。夸克链接进入夸克目录；115、磁力、ED2K 和普通下载链接进入 115 目录。

更改目录只影响之后提交的链接，不会移动历史内容。

这里配置外部服务完成事件触发 STRM 增量扫描。详细调用方法见本手册“外部完成 Webhook”。

## 13. 常见完整流程

### 13.1 新增一部电影并在 Emby 播放

1. 在发现页找到电影并核对年份。

2. 选择候选与目标网盘，提交转存。

3. 在任务中心等待转存和整理完成。

4. 确认影片位于已勾选的 STRM 来源目录。

5. 运行对应网盘的增量 STRM。

6. 等待 Emby 自动刷新或在 Emby 手动扫描。

7. 从电视或手机实际播放，确认播放地址对设备可达。

### 13.2 为连载剧建立追更

1. 先转存已有季集并核对网盘路径。

2. 从详情页创建追更，选择季、网盘和保存路径。

3. 查看追更卡片中的已播和已存进度。

4. 手动运行一次，确认无误后再等待计划任务。

5. 遇到待确认时核对集数；遇到暂无资源时保留任务稍后再试。

6. 新集完成后检查增量 STRM 和 Emby 入库消息。

### 13.3 只为现有网盘目录建立 STRM

1. 不配置 PanSou，也不必创建转存规则。

2. 连接对应网盘。

3. 在 STRM 页面选择来源根目录，读取并勾选需要处理的子目录。

4. 设置 `/strm` 输出和可访问的播放地址。

5. 首次执行全量扫描，以后执行增量或设置 Cron。

6. 在 Emby 添加与该输出目录对应的媒体库。

### 13.4 从手机提交链接

1. 配置企业微信自建应用或 Telegram 并发送测试消息。

2. 在云下载设置中为夸克与 115 选择目录。

3. 向 Bot 发送一条可恢复的小链接测试路由。

4. 从回复、站内活动和网盘目录核对结果。

5. 确认无误后再用于日常下载。

## 14. 更新、备份与恢复

### 14.1 更新前备份

至少备份：

- `./data`：数据库、配置和应用状态。

- `./strm`：当前媒体库入口文件。

- `./downloads`：本地任务输出（如使用）。

- `docker-compose.yaml` 及同级 `.env`：端口、挂载、账号和 PUID/PGID。

建议在容器停止或没有任务写入时复制 `data`，并定期验证备份能否恢复。

### 14.2 更新镜像

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 media-index
```

更新后依次检查：

1. 管理页可以登录。

2. 网盘与 TMDB 测试连接通过。

3. 历史任务、追更和愿望单仍存在。

4. STRM 播放地址没有变化。

5. 用一个现有媒体实际播放。

### 14.3 从 0.6.0 以前版本升级

当前版本使用一个 `media-index` 容器同时提供管理与播放服务。升级旧版时：

1. 备份数据、STRM 和旧 Compose。

2. 换用仓库当前 Compose，保留 `8000:8000` 与 `8097:8097` 两个映射。

3. 移除旧的独立播放容器。

4. 启动后保存播放器实际可达的 STRM 播放地址。

5. 如果旧 `.strm` 仍包含旧端口或 `127.0.0.1`，执行一次全量扫描更新。

已有数据库和网页设置不需要重建。

### 14.4 回滚

回滚前先确认目标版本是否支持当前数据库。优先恢复升级前备份，并把镜像从 `latest` 改为明确版本标签；不要只替换数据库文件的一部分。

## 15. 常见问题

### 登录后设置没有保留

检查 `./data:/app/data` 是否正确挂载且可写。不要只把数据库文件挂载到临时目录；容器重建后仍应使用同一个持久化目录。

### 夸克或 115 测试连接失败

确认凭据完整且未过期，容器时间正确，并且 NAS 可以访问对应服务。重新保存后再测试。不要把 Cookie 发到公开日志或 Issue。

### TMDB 或 Telegram 无法访问

先从容器网络检查目标服务是否可达；需要代理时在网络代理页填写容器可访问的代理地址。保存后单独测试服务。

### PanSou 地址测试失败

同一 Compose 网络应使用服务名和容器端口；独立部署应使用 MediaIndex 容器可访问的主机地址。`localhost` 指向 MediaIndex 容器自身，通常不是 PanSou。

### 任务一直排队或重复提交

先等待当前同类任务结束并刷新任务中心。定时任务、Webhook 和手动点击可能同时触发；短时间完成事件会尽量合并，但不应反复点击按钮。

### 智能追更显示的集数不正确

先核对 TMDB 季数和播出日期，再检查网盘保存路径与文件命名。特殊篇、合并集或不规则命名可能需要手动选择缺集或修正目录。

### 当天没有新资源却出现待确认

待确认表示找到了无法安全选择的候选，不等于已经找到可转存的新集。打开详情核对年份、季集和候选来源；不合适时可暂不处理。

### STRM 没有生成

确认对应网盘已连接、来源根目录正确、至少勾选并保存了一个直接子目录、输出目录可写。自动生成只处理成功转存到该网盘且位于保存范围内的内容。

### STRM 能入库但不能播放

打开生成的 `.strm` 检查主机和端口。播放地址必须能从 Emby 和客户端访问，并指向 302 端口而不是管理端口。使用反向代理时确认代理目标、HTTPS 证书和大文件播放请求正常。

### Emby 刷新后没有识别媒体

确认 Emby 媒体库指向正确 STRM 目录、命名符合库类型，并查看 Emby 自己的扫描日志。MediaIndex 负责生成入口和请求刷新，不决定 Emby 的元数据匹配结果。

### 删除同步提示未找到精确映射

不要尝试放宽匹配。核对这条媒体是否由当前 MediaIndex 生成、Emby 事件路径根是否填写正确，以及 STRM 是否被手工移动或重命名。修复映射后再测试。

### 磁力或普通链接不能提交

这类链接需要启用并连接 115，同时配置 115 云下载目录。夸克只接收夸克分享链接。

### Webhook 返回 401、409 或 503

`401` 重新核对完整密钥；`409` 回到页面保存目标网盘和有效扫描范围；`503` 检查网盘连接和当前任务状态。调用端应使用管理端口。

### 封面预览慢或替换失败

确认 Emby 连接有效、媒体库中有可用海报或背景图，并先用 480p 和默认字体测试。预览不修改 Emby；只有“立即替换”或定时任务会写入。批量操作期间不要重复点击。

## 16. 安全与使用边界

- 只连接你自己的账号，并确保对相关内容拥有合法访问与使用权。

- 不要公开 Cookie、Token、API Key、Webhook 密钥、完整配置文件或带私密参数的 URL。

- 管理端口不建议直接暴露到公网；需要外部访问时使用 HTTPS、强密码和可靠的反向代理访问控制。

- 播放入口如需公网访问，同样应配置 HTTPS、合理的访问范围和日志保护。

- 自动转存、跨盘复制、定时任务和删除联动都应先用小范围数据验证。

- 定期备份数据和 STRM，并保留网盘回收站作为删除同步的恢复窗口。

- MediaIndex 不提供资源，也不替你判断第三方内容的版权、准确性或安全性。完整责任边界见 [DISCLAIMER.md](../DISCLAIMER.md)。
