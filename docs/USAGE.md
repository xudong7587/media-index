# MediaIndex 使用手册

MediaIndex 是面向个人 NAS 的网盘媒体转存入口与维护中心。它不提供资源，只把你自行配置的 TMDB、PanSou、原生夸克、115、OpenList、Emby 和通知渠道串成一套可追溯的自动化流程。

## 1. 部署方式

### 1.1 只部署 MediaIndex

1. 新建部署目录并下载仓库根目录的 `docker-compose.yaml`。
2. 修改 `MEDIA_USER` 和 `MEDIA_PASS`，不要使用示例密码。
3. 执行：

   ```bash
   docker compose up -d
   ```

4. 访问 `http://NAS_IP:8000`。容器内部的 STRM/302 服务固定监听 8097；标准 Compose 默认映射为 `8000:8000` 与 `8097:8097`，可只改左侧 NAS 端口。管理面板与播放端口必须同时保留。
5. 登录后进入 **设置**，填写已有 TMDB、PanSou、原生夸克、115、OpenList 和通知渠道配置。

将 Emby 扫描的 STRM 目录挂载到容器 `/strm`，例如 `- /volume1/Media/Strm:/strm`。宿主机播放端口不是 8097 时，请在 **STRM 与 302 → STRM 通用设置** 中填写完整的 STRM 播放地址（内网 `http://NAS_IP:8097` 或对外反代域名）。该地址不能填写管理端口 `8000`，容器无需配置 `EMBY_PROXY_PORT`。

PanSou 地址由管理面板保存，不需要 `PANSOU_URL` 环境变量。如果 PanSou 或 OpenList 不在同一 Docker 网络里，请填写 MediaIndex 容器内可访问的地址，不要填写容器自己的 `127.0.0.1`。

### 1.1.1 升级到 0.6.0 及以后版本

0.6.0 把 302 播放服务放进同一个 `media-index` 容器。升级前先备份 `./data`，然后使用仓库当前的 Compose：

```yaml
ports:
  - "8000:8000"  # 管理面板；左侧按 NAS 端口规划替换
  - "8097:8097"  # STRM/302 播放；左侧按 NAS 端口规划替换
volumes:
  - ./data:/app/data
  - /volume1/Media/Strm:/strm # 改为 Emby 实际扫描的 STRM 目录
```

随后执行 `docker compose pull && docker compose up -d`。不要保留旧的独立播放容器，也不要把宿主机播放端口写到 `EMBY_PROXY_PORT`；容器内部端口固定是 8097。登录管理页后，在 **STRM 与 302 → STRM 通用设置** 保存能被播放器访问的内网或外网播放地址。已有 `.strm` 若仍包含旧端口或 `127.0.0.1`，保存正确地址后重新全量扫描一次即可更新。

### 1.2 一套 Compose 部署 MediaIndex 和 PanSou

仓库的 `docker-compose.yaml` 已预留 PanSou 服务和缓存卷，默认均被注释。

1. 删除 `pansou` 服务整段每行开头的 `# `。
2. 删除文末 `volumes` 中 `pansou-cache` 定义每行开头的 `# `。
3. 修改 MediaIndex 的 `MEDIA_PASS`。
4. 执行：

   ```bash
   docker compose up -d
   ```

5. 默认入口：

   | 服务 | 默认地址 | 用途 |
   | --- | --- | --- |
   | MediaIndex | `http://NAS_IP:8000` | 主控制台；端口可在 Compose 左侧调整 |
   | STRM/302 | `http://NAS_IP:8097` | 同一 MediaIndex 容器的播放入口；端口可在 Compose 左侧调整 |
   | PanSou | `http://NAS_IP:8888` | 资源搜索 API |

同套 Compose 启用 PanSou 后，使用浏览器进入 MediaIndex 管理面板，把 PanSou 地址填为 `http://pansou:8888`；不需要重新编辑 Compose 或重建容器。默认 Compose 网络已是项目隔离的 bridge 网络，两个服务会自动互通。

## 2. 首次配置

进入 **设置 → 基础设置** 后，建议按这个顺序配置。

### 2.1 通用服务

- **TMDB API Key**：用于搜索媒体、读取季集、播出日期、海报和简介。
- **PanSou 地址**：用于搜索网盘资源。MediaIndex 会生成多关键词搜索策略，再从结果里挑可验证的候选。
- **网络代理**：如果 TMDB 或 PanSou 需要代理，在 **设置 → 网络代理** 填写 HTTP/HTTPS 代理。

保存后使用页面里的测试按钮确认连接正常。设置页各分区共用屏幕右下角固定的圆形保存按钮；切换分区前先保存当前修改。

### 2.2 原生夸克

1. 进入 **网盘工作台 → 网盘连接 → 夸克**。
2. 从已登录的夸克网页复制 Cookie 并保存。
3. 点击“测试连接”；成功后再启用夸克作为搜索和转存来源。

MediaIndex 直接使用夸克 Cookie 读取分享、目录、转存和改名，不需要部署 QAS。

### 2.3 原生 115

MediaIndex 原生支持 115 分享读取、文件匹配、转存、改名、移动和目标目录确认，不要求 MoviePilot 执行转存。

1. 进入 **设置 → 基础设置 → 115**。
2. 粘贴包含 `UID`、`CID`、`SEID` 的 115 Cookie。
3. 或填写 MoviePilot 后端地址和 API Key，从 `P115StrmHelper` 插件安全导入 Cookie。
4. 填写 115 保存根目录、115 网盘暂存目录和 115 转存本地目录。
5. 点击“测试连接”。

115 的 **网盘暂存目录** 位于 115 网盘内，用于先接收、核对、改名，再移动到最终目录。它不是 NAS 本地目录。

115 的 **转存本地目录** 用于“存本地”工作流，需要挂载进 MediaIndex 容器。默认 Compose 使用 `./downloads:/downloads`。

Cookie 是完整账号凭据，只保存在服务端数据目录的 `.env` 中，配置接口不会返回 Cookie。不要截图、转发或提交到 Git。

### 2.4 保存路径、分类路径和命名

夸克和 115 有独立的保存根路径与分类路径。分类路径支持：

- 电影
- 电视剧
- 综艺
- 演唱会
- 纪录片
- 动漫
- 自定义分类

分类路径右侧的文件夹按钮会直接使用当前 Provider 的凭据读取目录：

- 夸克：通过原生 Cookie 读取目录。
- 115：通过 115 Cookie 读取目录。

命名规则位于 **设置 → 基础设置 → 命名与分季**：

- 媒体文件夹命名规则，例如 `{title} ({year})`
- 季文件夹命名规则，例如 `Season {season}` 或 `S{season:02d}`
- 电影文件命名规则，例如 `{title}.{year}`
- 剧集文件命名规则，例如 `{title}.{year}.S{season:02d}E{episode:02d}`

开启“剧集按季分目录”后，新任务会保存到媒体目录下的季目录；旧任务路径仍保持兼容识别。

## 3. 发现、搜索和转存

### 3.1 发现页

发现页从 TMDB 获取电影、剧集、综艺、演唱会、纪录片和动漫。卡片支持：

- 打开详情。
- 刷新资源状态。
- 加入智能追更。
- 选择单个网盘转存。
- 一键转存所有有资源的网盘。

如果某个资源只有夸克或只有 115，MediaIndex 会只转存有资源的一边。发现详情不会默认执行 OpenList 补齐；先开启“允许自动同步”，并在本次转存旁显式点亮 OpenList 标记，才会按配置方向补齐目标网盘。

### 3.2 单次转存流程

1. 选择媒体和季。
2. MediaIndex 先用 PanSou 搜索候选分享。
3. 标准电影若能从 PanSou 标题、年份和真实文件唯一确认，会跳过 TMDB 直接生成转存任务；其他情况再用 TMDB 匹配规范媒体信息。
4. 原生夸克或 115 Provider 读取分享内真实文件。
5. 综艺匹配标题、年份、季、播出日期、期数、分段和文件类型；同一期分多日发布时，会结合 TMDB 分集上下文判断新上传的连续分段。电影、电视剧主要核对名称、年份和季集标记。
6. 证据足够时自动转存并按命名规则重命名。
7. 证据不足时进入 **待确认**。

剧集和电影如果能从文件名、标题和季集结构直接确认，就不额外做复杂核验；其中标准电影还可以在 PanSou 阶段跳过 TMDB。综艺命名常包含“第几期”“上/下”“（一）/（二）/（三）”“纯享版”等不稳定信息，会更依赖 TMDB 日期、期数和分段信息做保守判断。这一层只验证 PanSou 已返回候选中的真实文件，不改变 PanSou 查询参数、搜索顺序或候选排序。

### 3.3 多季转存

多季剧集可以同时选择多个季。MediaIndex 会按 `Provider × Season` 建立独立子任务：

- 前面已完结季优先寻找完整包。
- 如果完整包中只有部分文件符合要求，会先转存可确认的部分，再继续寻找缺失内容。
- 最后一季可以作为追更季处理。
- 一个 Provider 失败不会回滚另一个 Provider 的成功结果。

## 4. 智能追更

智能追更的核心逻辑是：**每次执行都读取目标网盘目录的真实状态，再决定从哪里开始追。**

### 4.1 创建追更

在发现卡片或详情弹窗中点击 **加入智能追更**，选择季和目标网盘。正在连载的剧集或综艺会默认加入追更。已经加入追更的季仍可手动转存。

### 4.2 自动执行规则

到达设定时间后，MediaIndex 会：

1. 刷新 TMDB 季集信息。
2. 读取目标网盘目录中实际存在的文件。
3. 识别已存集数。
4. 从最后一集的下一集开始搜索。
5. 只有目录一集都没有时，才按初始全量资源处理。

历史缺集不会被自动回头补，除非你手动勾选缺失集并点击 **补齐所选**。这样可以避免日常追更反复搜索早期旧资源。

调度器每轮选择到期任务前会刷新活动任务的 TMDB 元数据。TMDB 新增加的已播集会写入分集列表，并重新计算下次检查时间，因此已经暂时休眠的追更任务也能在新集上线后恢复巡检。

### 4.3 卡片状态

智能追更卡片会显示：

- 当前运行状态。
- TMDB 已播集数。
- 夸克和 115 已确认集数。
- 下次巡检时间。
- 近期执行消息。
- 每个网盘每一集的已存、缺失和未来状态。

展开分集下拉时会先显示刷新后的 TMDB 集数，并使用 `E26`、`E27` 这类简洁标签；115 目录读取较慢或暂时不可用时，不会阻塞 TMDB 分集列表。点击刷新时，系统仍会重新读取网盘真实目录，不继承历史缓存作为最终状态。

### 4.4 重试和待确认

- PanSou 尚未收录当天内容，或候选分享里只有上一期文件时，任务保持等待并按巡检设置重试，不生成待确认通知。
- 候选文件确实覆盖目标集，但日期、期数或分段存在歧义时，才进入 **待确认**。
- 待确认用于让用户判断真实歧义，不用于提醒“资源还没更新”。

## 5. OpenList 自动同步

OpenList 用于已挂载的夸克媒体库和 115 媒体库之间复制文件。它不替代原生夸克或 115 转存，只负责两边文件补齐。

### 5.1 启用

进入 **设置 → OpenList 同步**：

1. 启用 OpenList 功能。
2. 填写 OpenList 地址和 Token。
3. 选择夸克媒体库目录和 115 媒体库目录。
4. 开启“允许自动同步”。
5. 选择自动同步方向；115 是主媒体库时建议选择“夸克 → 115”。

OpenList 同步路径使用 OpenList Token。分类路径和通知下载路径使用夸克/115 原生 Cookie；115 目录读取不会回退到 OpenList 存储。

### 5.2 自动同步较新资源

发现卡片的补齐只在用户为本次转存显式点亮 OpenList 标记且确实需要时触发：夸克已验证并完成转存、115 没有可用资源、OpenList 已配置且方向允许 **夸克 → 115**。未标记时不执行这一环节。缓存的发现链接会在执行前重新验证；失效的 115 链接不会被提交，也不会阻止夸克转存。只有这条路径成立，详情内的流程预览才显示 OpenList 步骤。

智能追更、愿望单或用户手动发起同步时，MediaIndex 会按任务需要对比两边目录：

- 只同步缺少的一边。
- 目标媒体目录不存在时，复制已经由 MediaIndex 改好名的整个媒体或 Season 文件夹；目标目录存在时只复制缺失文件，并跳过同名文件。
- 相同目录已有同步任务在运行时，不重复触发。
- 任务会显示在右上角执行任务窗口。
- 自动同步由上述业务事件触发，不会每隔若干秒轮询或递归扫描整个媒体库。
- 自动同步可选夸克 → 115、115 → 夸克或双向。该设置只约束自动触发；手动同步和追更卡片中的手动补齐不受限制。
- 多网盘同时搜索时，只有本次已显式标记 OpenList 补齐且同步任务覆盖缺失网盘，才会把另一侧的“无资源”视为可补齐结果。

智能追更卡片中，如果后台检测到某个网盘正在自动同步，会显示“自动同步中”的转圈状态。

### 5.3 手动同步

进入 **设置 → OpenList 同步 → 手动同步**：

- 左右两边分别浏览夸克媒体库和 115 媒体库。
- 点击目录名进入文件夹。
- 勾选文件后可向另一边复制。
- 可选择跳过已存在或覆盖已存在。
- 支持按文件名、类型和时间排序，重复点击切换正序/倒序。

## 6. STRM、302 与媒体服务器

### 6.1 STRM 通用设置

**STRM 与 302 → STRM 通用设置** 负责容器内 302 端口与 STRM 播放地址；管理端口、Emby 实际地址和播放地址是三件不同的事：

- 管理面板：Compose 的 `8000:8000`，只打开 MediaIndex。
- 播放入口：Compose 的 `8097:8097`，供 `.strm` 与外部播放器请求 `/api/play/...`。
- Emby 实际地址：例如 `http://NAS_IP:8096`，填在 Emby 服务器连接中，用于 API 刷新媒体库。

若使用反向代理，STRM 播放地址填反代后的 302 域名；若只在内网使用，可填 `http://NAS_IP:8097`。不要把 `127.0.0.1` 写入 STRM，因为 Emby、电视和其他播放器会把它理解为各自本机。

### 6.2 生成与入库

分别在 **115 STRM** 或 **夸克 STRM** 中选择来源目录和 `/strm` 下的输出目录，然后点击“读取子目录”并至少勾选一个需要生成的直接子目录。选择会长期保存并在重新打开页面后恢复；未勾选任何目录时，手动扫描、Cron 周期增量、转存后联动和 Webhook 增量都会拒绝启动，不会退回默认全盘扫描。手动全量、手动增量、Cron 周期增量、115 生活监控和 Webhook 触发增量都会完整分页遍历当前已选范围，不设置 10,000 文件总量上限；500 条只是高效批量写入本地数据库的批次大小。扫描任务会在右上角运行日志显示当前扫描目录。启用 Emby 自动入库后，MediaIndex 会按输出目录匹配 Emby 媒体库位置并请求刷新；匹配不到才需要在 Emby 设置中选择媒体库。

STRM 清理有独立安全门：增量扫描只创建、替换和校验，永远不清理缺失项；远端返回空清单、只返回图片/NFO 等旁路文件、分页中断或鉴权失败时都跳过清理。只有远端视频枚举明确完成且非空的全量扫描才可处理缺失映射。第一次完整全量扫描未发现时只标记 `pending_remove`，文件仍保留；连续第二次完整全量扫描仍缺失才进入精确路径删除。计划删除超过当前扫描范围 10%（小范围至少允许 1 条）或超过 50 条时触发熔断，本轮不删除任何 STRM。批量路径归一化变化会在写文件前触发路径迁移熔断；修改扩展名、最小体积或排除关键词不会把已经生成的精确映射误判为缺失。清理范围同时限定 `provider`、`inventory_root_path`、`library_root_id` 和已选择的直接子目录。

### 6.3 媒体库封面工坊

**媒体服务器 → 媒体库封面工坊** 分为基础设置、封面风格、标题设置和更多参数四页，提供圆角海报堆叠、斜向多海报组合、单海报斜置和纯文字四种静态模板。基础设置可选择批量及定时刷新所处理的媒体库并保存更新周期；未勾选表示全部。每个媒体库可以分别保存中英文标题，风格、图片来源、排序、分辨率、字号缩放、偏移、间距、背景模糊或渐变、颜色提取比例和自定义背景色也会长期保存。

预览不写入 Emby；点击“生成并替换当前媒体库”或批量生成按钮才上传。MediaIndex 会按 Emby 图片接口要求上传 Base64 JPEG，并在成功后强制刷新实际媒体库封面，旧图不会继续被浏览器缓存。生成时只临时读取 Emby 当前媒体库的海报：多海报样式最多读取 9 张，其余样式读取 1 张；媒体库没有海报时会提示无法生成。动态模板已明确剔除。

该工坊的静态生成器按 GPL-3.0 整合，MediaIndex 从 `0.6.1` 起整体按 GPL-3.0 发布；详细上游归属见仓库根目录的 `THIRD_PARTY_NOTICES.md`。

## 7. 待确认

待确认代表系统已找到可能资源，但不能安全自动执行。处理建议：

- 先看候选标题、年份、季和来源。
- 再看分享中的真实文件。
- 可以只勾选确定的文件继续转存。
- 明显不相关的候选可以删除或重新搜索。

企业微信自建应用启用交互回调后，或 Telegram Bot 配置允许的 Chat ID 后，待确认任务也可以在手机端回复编号或使用 Telegram 按钮处理。

## 8. 愿望单

愿望单适合还未开播、资源尚未出现或暂时找不到的媒体。

- 每个愿望单都可单独开启或暂停巡检；暂停不会删除愿望。
- 电影以上映日期、剧集和综艺以 TMDB 首播日期为基础开始巡检，小时可由用户自定义。
- 可切换目标网盘。
- 可手动点击立即执行。
- 进入待确认后可在网页、企业微信或 Telegram 中选择候选。

在 **网盘工作台 → 转存和整理规则** 中可设置资源排除关键词，例如 `TC`、`抢先`、`预览版`、`480p`。MediaIndex 会在候选排序和分集文件选择两层排除命中的资源；关键词由用户自行增删，不影响已经转存的文件。

## 9. 通知和交互

网页内通知显示在右上角小铃铛。外部通知位于 **设置 → 通知设置**，支持：

- 企业微信自建应用。
- 企业微信群机器人。
- Telegram。

媒体类外部通知优先发送带海报的图文卡片；播放、入库和删除同步通知会先等待并重试读取内网 Emby 的背景图或主海报，将图片缓存为 MediaIndex 可访问地址后再发送，因此可能比纯文字慢几秒。成人媒体等没有 TMDB 图片的条目也会优先使用 Emby 图片；删除时若 Emby 条目已经消失，还会尝试同目录旁路海报和同一媒体文件夹的缓存海报。同一文件夹的一批删除只保留一条运行日志并发送一张聚合通知。转存阶段尚未入库时才使用 TMDB 海报；只有图片确实不可用或渠道图文发送失败时才安全回退为文字。建议填写手机和企业微信/Telegram 服务器可访问的 **公网访问地址**，用于读取缓存图片和打开详情页面。

### 9.1 企业微信自建应用

填写：

- 企业 ID（CorpId）
- 应用 Secret
- AgentId
- 接收成员、部门或标签
- 企业微信 API 地址

保存后点击测试按钮。

### 9.2 企业微信交互回调

填写：

- 回调 Token
- EncodingAESKey
- 允许指令的成员 UserID

页面会生成企业微信后台需要填写的回调 URL。企业微信后台、MediaIndex 和应用可见范围要保持一致。

### 9.3 Telegram 交互

启用 Telegram，填写 Bot Token 和允许交互的 Chat ID。MediaIndex 通过 Bot API 轮询消息；只有配置列表中的 Chat ID 可以触发搜索、转存、编号确认和按钮操作。Telegram 与企业微信自建应用共用下面的指令和交互设置，企业微信群机器人仅发送通知。

### 9.4 可用指令

| 消息或指令 | 功能 |
| --- | --- |
| `资源名` | 搜索影视并默认保存到网盘；多个匹配时返回编号 |
| `本地 资源名` | 搜索影视并保存到本地 |
| `分享链接` | 夸克或 115 分享链接直接转存到默认路径 |
| `磁力链接` | 固定提交到 115 离线下载 |
| `1`、`2` 等数字 | 确认当前资源、待确认任务或候选 |
| `/review` | 查看待确认任务 |
| `/status` | 查看追更、愿望单、待确认和未读通知数量 |
| `/tracking` | 查看最近智能追更任务 |
| `/wishlist` | 查看最近愿望单任务 |
| `/strm_full` | 对所有已启用且已选择子目录的网盘执行 STRM 全量扫描 |
| `/strm_incremental` | 对所有已启用且已选择子目录的网盘执行 STRM 增量扫描 |
| `/download` | 提示用户输入资源名称或下载链接 |
| `/notifications` | 查看最近通知 |
| `/cancel` | 取消当前等待中的编号选择 |
| `/help` | 查看指令帮助 |

编号选择按企业微信 UserID 或 Telegram Chat ID 独立保存，有效期为 30 分钟。

在 **全局设置 → 通知和交互 → 交互指令** 可自定义快捷操作。保存后，Telegram 会更新 Bot 命令列表，企业微信自建应用会更新底部菜单；服务重启后也会自动恢复：STRM 全量/增量会自动遍历所有“已启用且已选择子目录”的网盘；智能追更会反馈状态并提供页面入口；添加下载会提示输入资源名称或链接。页面宽度不足时菜单保留图标，并通过悬停提示功能。

### 9.5 下载链接自动转存

企业微信自建应用和 Telegram 收到下载链接后会自动进入云下载流程。路由说明和最近记录位于 **全局设置 → 通知和交互 → 云下载设置**。

可设置：

- 参与交互的网盘：夸克和 115 可同时勾选；资源名会对已勾选网盘发起转存。
- 磁力/电驴默认网盘固定为 115；分享链接仍按链接类型选择对应网盘。
- 夸克和 115 各自的云下载目录。

在 **网盘工作台 → 转存和整理规则 → 夸克/115 规则** 中设置云下载目录，目录选择按钮会根据对应网盘读取真实目录：

- 夸克：通过原生 Cookie 读取目录。
- 115：只使用 Cookie 读取目录。旧 Open 配置字段会为升级兼容保留，但不会参与原生 115 操作。

支持范围：

- 夸克分享链接：自动转存到夸克云下载目录。
- 115 分享链接：自动转存到 115 云下载目录，需配置有效 Cookie。
- 磁力、ed2k、HTTP/HTTPS 下载链接：固定提交到 115 云下载目录，需使用有效的 115 Cookie。
- 发现页的 **链接下载** 使用相同规则，并可在提交前选择云下载目录下的子目录或媒体分类。

115 离线下载提交后，MediaIndex 会短时间查询 115 任务状态：如果 115 已经秒存完成，会返回“115 云下载完成”；如果 115 明确失败，会返回 115 提供的失败原因；如果 115 仍在处理，会提示任务已提交且仍在处理中。长时间下载进度以 115 客户端或 115 网页端的离线下载任务列表为准。

### 9.6 外部服务完成 Webhook

该功能用于这条链路：外部刮削器、整理器或其他容器完成任务 → 通知 MediaIndex → MediaIndex 对指定 115/夸克来源目录执行一次 STRM 增量同步 → 如有新增或替换再通知 Emby 刷新。它不绑定特定软件，只执行增量扫描，不会因 Webhook 的空 Body、错误路径或不完整清单清理历史 STRM。

先在 MediaIndex 配置：

1. 进入 **全局设置 → 通知和交互 → Webhook**。
2. 选择 **115** 或 **夸克**。页面会只读显示对应网盘 STRM 页面已保存的来源根目录和勾选子目录；Webhook 不能另行扩大扫描范围。没有勾选子目录时无法启用。
3. 合并等待建议保留 30 秒。外部服务逐项发送完成事件时，MediaIndex 会不断重置这段等待时间，最后只执行一次增量扫描。
4. 点击“生成新密钥”会同时开启 Webhook。必须先点击“保存并启用”，等页面显示“已启用并保存”后，才能显示或复制完整 URL。完整 URL 带有密钥，不能公开分享。

再到外部服务的 Webhook 设置：

1. 开启 Webhook，新增 Endpoint，名称可填 `MediaIndex 增量同步`。
2. 请求方式选择 **POST**。
3. URL 粘贴 MediaIndex 页面生成的完整 Endpoint URL。
4. 触发事件只勾选 **成功/完成**，例如 `finished`、`completed` 或 `success`；不要勾选失败事件。
5. Headers 留空。Body 模板（JSON）也可留空；MediaIndex 不采信外部 Body 中的 provider 或路径。如服务要求填写 JSON，可使用：

   ```json
   {"event":"finished"}
   ```

外部容器必须能访问 Endpoint URL。如果两个容器在同一 Docker 网络，可使用 MediaIndex 的容器服务名与管理端口：

```bash
curl -i -X POST 'http://media-index:8000/api/webhooks/strm-incremental?token=完整密钥' \
  -H 'Content-Type: application/json' \
  -d '{"event":"finished"}'
```

返回 `HTTP 202` 且状态为 `scheduled` 或 `coalesced` 即表示已经接收并安排增量任务。不在同一网络时，把主机和端口换成外部容器能访问的 NAS 地址；容器内不要填写 `localhost` 或 `127.0.0.1`。Webhook 使用管理/API 端口，不使用 STRM/302 播放端口 8097。MDC-NG 可作为其中一种外部服务：请求方式选 POST，只勾“刮削成功（finished）”，触发分类可按需要选择，Headers 和 Body 均可留空。

## 10. 运行日志和设置保存

顶部栏的运行日志按钮会打开独立的居中弹窗。弹窗每 2.5 秒刷新一次，可查看：

- 当前任务阶段，例如 TMDB 解析、目录检查、PanSou 搜索、文件匹配、提交转存和网盘确认。
- 后端返回的具体执行消息、目标保存路径、源文件、重命名结果以及开始/结束时间。
- 全部、进行中、异常和计划任务筛选，并可终止单个运行中任务或全部活动任务。智能追更巡检、愿望单巡检和 115 生活监控各自只保留最近一次状态。
- Webhook 会先显示“等待合并同批次完成事件”，随后在同一任务中显示增量扫描和生成结果。

点击弹窗右上角 **关闭**、按 `Esc` 或点击遮罩空白处均可关闭。任务仍会在后台继续执行；关闭弹窗不会停止任务。

设置页面的保存入口固定在屏幕右下角。圆形按钮只提交当前设置分区对应的表单，不会因为页面滚动而消失。

## 11. 更新、备份和恢复

更新：

```bash
docker compose pull
docker compose up -d
```

备份前停止服务，然后备份：

- `./data`：MediaIndex 配置、SQLite 数据库和缓存。

## 12. 常见问题

### 夸克测试连接失败

重新从已登录的夸克网页复制完整 Cookie，并确认没有换行或已过期。保存后再点击“测试连接”。

### 115 测试连接失败

确认 Cookie 包含 `UID`、`CID`、`SEID`，且没有换行。Cookie 过期后需要重新获取。

### 容器之间无法连接

同套 Compose 要让 MediaIndex 和 PanSou 都在同一个 Docker 网络。独立部署时，填写 MediaIndex 容器内可访问的服务地址。

### 智能追更刷新后集数不对

先展开卡片确认 TMDB 分集列表是否已经出现新集。TMDB 集数已出现但网盘状态不对时，再确认对应网盘的实际目录是否存在，路径是否符合当前分类路径和命名规则。刷新会直接读取网盘真实目录；如果目录名称不标准，系统会尝试宽松匹配，但仍建议统一使用 MediaIndex 的命名规则。

### 当天没有新资源却反复提示待确认

`0.5.15` 起，PanSou 候选尚未包含目标新集时会静默重试，不应创建待确认。升级后如果仍出现旧通知，可先查看顶部运行日志确认任务时间和目标集数；已有历史待确认记录不会被当作新资源重新转存。

### Emby 删除同步提示“未找到精确 STRM 映射”

升级到包含本修复的 `0.6.7` 后，MediaIndex 会优先按 STRM 通用设置中的共同根目录解析 Emby 路径。例如 Emby 上报 `/strm/02系列电影/影片/影片.strm` 时，会保留 `02系列电影/...` 与 `strm_entries.relative_path` 精确匹配，不再被更深的媒体库虚拟路径错误截短。已有状态为 `ready` 或 `pending_remove` 且仍能精确关联唯一 115 `file_id` 的记录都可直接联动删除，一般不需要重新生成 STRM；没有映射、映射不唯一或只有文件名相同的项目仍会拒绝删除网盘文件。

同一个 Emby 删除事件只处理一次，失败事件也不会在后台无限重试。升级前已经失败的事件不会自行补删；升级后请用另一个测试条目验证，或在确认 STRM 映射仍存在后重新触发一个新的删除事件。切勿为了让删除“猜中”而按文件名批量清理。

### 磁力链接不能提交

确认 115 Cookie 有效，并在 115 转存规则中设置了可写的云下载目录。夸克当前不支持磁力离线下载。

### 增量同步 Webhook 返回 401、409 或 503

- `401`：外部服务中粘贴的完整 URL 密钥与 MediaIndex 当前保存密钥不一致；重新复制完整 URL。
- `409`：页面开关尚未保存或 Webhook 未启用；返回设置页保存，确认状态显示“已启用并保存”。
- `503`：没有配置 STRM 输出目录、来源目录，或后台调度器未能启动。先检查对应网盘 STRM 设置。
- 外部服务日志显示请求成功但没有立即扫描：这是合并等待时间在生效；同批次最后一个完成事件后才执行一次。

## 13. 安全提示

- MediaIndex 和反向代理都应使用强密码。
- TMDB Key、夸克/115 Cookie、OpenList Token、通知凭据和完整 Webhook URL 都不得提交到 Git。
- 建议仅在内网、VPN 或可信 HTTPS 反向代理后使用。
- 本项目不提供任何资源、Cookie 或网盘账号，使用者需自行确保使用行为合法合规。
