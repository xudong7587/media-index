# STRM 播放探测与按来源删除

Primary Module：`strm`。跨模块依赖限于 `cloud` 既有夸克原生回收接口、`media-server` 的 Emby Webhook 分派，以及 Shared/Core 的独立自动执行配置；不修改数据库结构或播放令牌格式。

## 线上只读证据

- v0.7.22 更新后，新旧 STRM 的 GET 均返回 206 和正确的 MP4 字节，已走认证转发；此前的夸克 412 问题不再复现。
- 同一入口 HEAD 返回 404。专用播放应用只注册 GET，HEAD 会落到 Emby 反向代理，而不是资产播放接口。
- 影片头部、中间、尾部各 1 MiB Range 均可读取；开头约 7.9 MB 的 moov 元数据也能完整读取，包含 avc1、mp4a 样本类型。普通无 Range GET 首批数据等待较长，原实现每次 read 要凑满 1 MiB。
- 诊断包的当前删除错误是找不到精确 STRM 映射，未证明实际发起了 115 回收。失败任务标题固定写着“Emby → 115”，会造成来源误判。

## 修复行为

- 播放路由支持 GET 和 HEAD。HEAD 只取上游响应头并关闭连接，不读视频正文；认证/令牌合同保持一致，115 可直连链接仍可重定向。
- 视频流优先用 read1 转发已到达的字节，单块上限 64 KiB；同时记录播放请求就绪/失败与流中断诊断，不记录播放路径、签名令牌、Cookie 或直链。
- 夸克普通 GET 和开放范围 GET（如 `bytes=0-`）向上游按最多 8 MiB 的有限范围顺序读取，对播放器仍返回完整的连续 200/206 响应。每段校验起止、总长度和正文长度；后续段沿用既有令牌核验与直链过期刷新，不重复已发送字节。固定范围和 HEAD 保持原有合同。
- STRM 删除从持久化资产映射读取 provider，按来源分别调用 115 或夸克。跨网盘同 ID 不混用，路径有歧义或来源身份无法确认时拒绝删除。
- 夸克回收前核验记录的账号（若有）、完整来源目录路径和父 ID、文件 ID、名称、大小及已知摘要；回收后完整读取父目录确认该 ID 消失。仅回收精确匹配的视频，保留目录及其他文件。未确认成功时保留映射。
- `QUARK_DELETION_AUTO_CONFIRM` 默认为 false，独立于原有 115 自动执行开关。Webhook 与媒体库根目录沿用公共设置，两个网盘页面分别保存自己的自动执行选项。
- 日志和通知使用实际来源网盘；尚未匹配来源的失败任务不再标注为 115。

## 验证与限制

修复后的本地真实 API 验证：HEAD 200、正确 5,874,856,210 字节长度、无正文；Range GET 206；普通 GET 首段约 0.41 秒开始返回（本机测试，不作为 NAS 性能承诺）。新增回归覆盖 HEAD、诊断脱敏、低缓冲首块、同 ID 跨网盘分派、回收身份变化、结果未确认及两个自动执行开关隔离。前端生产构建通过。

没有执行真实删除，没有修改 NAS 服务。HEAD 与缓冲修复的本地通过不等于播放器端验收完成。

## Emby 日志补充

用户随后提供的 `embyserver.txt` 显示，14:01:24 和 14:10:06 对该视频外网播放入口的 ffprobe 调用均在约 60 秒后超时，PlaybackInfo 请求也因此耗时约 60.5 秒。日志中的 ffprobe stderr 只有启动横幅，没有具体 HTTP 失败或解码错误，因此不能仅凭超时判断为 DNS、回环路由、TLS 或上游读取中的某一种原因。

## 用户授权 SSH 诊断与分段对照

2026-09-14 用户登录 NAS 的 Lucky SSH 终端并授权检查 Emby、MediaIndex 日志。所有检查与临时对照均未修改现有容器、配置、媒体文件或云盘文件。

- 从 Emby 容器访问内网和公网播放服务的 `/health` 均为 200，约 1.5 ms 与 16 ms。实际固定前 1 MiB 的视频请求，两条路径均返回完整 206，约 0.26 秒与 0.16 秒。
- 使用 Emby 的 User-Agent、Connection 和 Range 请求头对内网视频请求 `bytes=0-`，响应头约 0.24 秒到达，但 8 秒内正文为 0；相同头下 `bytes=0-1048575` 在约 0.93 秒收到完整 1 MiB。
- Emby 自带 ffprobe 的调试输出确认 TCP 已连接、发出了开放范围 GET，随后没有读到可用于识别的媒体数据并超时。内外网均可复现；因此不是必须更换域名或 STRM 内外网前缀的问题。
- 直接读取上游的开放范围，read1 首次约 0.51 秒收到 7,258 字节，后续持续以小块到达；read(1 MiB) 约 10.17 秒才返回。明确请求 8 MiB 范围后，前 1 MiB 约 0.26 秒返回。仅降低本地缓冲不能证明大块 MP4 元数据能在探测时限内完整到达。
- 临时分段代理仅在 Emby 网络命名空间的 localhost 上运行，使用现有安全下载链接和请求头，每段最多 8 MiB、下游持续转发。测试后自动关闭。相同 Emby ffprobe 在 **2.349 秒**识别成功：H.264、1920×900、AAC、9052.042 秒、5,874,856,210 字节。

该对照验证了分段读取方案；本地正式实现另加范围/总长度/短读核验与刷新回归。它不是在 NAS 上部署了修复，也不等于绿联或 Emby 客户端已经完成正常播放验收。发布后仍需用户实际起播和拖动验证。
